# JPEG 與 IndexedDB 本機試做

本機試做完成，尚未發佈正式網站。先前調查報告與 CSV 保留為修改前基準。

## 圖片

- 四張主星球與自然入口：5 張，13,720,301 → 3,125,135 bytes，減少 77.2%。
- 現行 gacha-collectibles.json 使用的收藏品：96 張，30,369,732 → 6,270,766 bytes，減少 79.4%。
- 原 PNG 全部保留。新增 JPEG 採品質 90、4:4:4、漸進式編碼；101 張逐一確認像素寬高與原圖一致。
- 收藏品的 ID、名稱、權重、稀有度與其他資料不變，只替換 asset 路徑。
- 視覺檢查包含原尺寸裁切比對（數學星球、自然入口、小兔及柴犬收藏品）；沒有發現明顯色偏、去背破壞或可見大塊壓縮瑕疵。JPEG 仍是有損格式，細節不會逐像素等同 PNG。
- docs/IMAGE_JPEG_PREVIEW.html 提供五張主入口及每個角色一張收藏品，共 17 組左右比對。
- 本輪未轉換透明分類圖、透明單元圖示、教材文字圖或繪本場景。

## 快取

- entry-image-manifest.js 列出 223 個 URL：先前 127 個共用入口／分類／控制圖片，加上 96 張收藏品；JPEG 路徑已同步。
- 目前清單的檔案總量為 40,180,550 bytes。快取上限 64 MiB；滿額時淘汰最久未使用項目。
- 僅保存頁面實際已請求的資源。不在登入前預抓所有科目、年級或收藏品。
- Service Worker 處理後续圖片請求；頁面以 Resource Timing 觀察首訪已下載的圖片與 CSS 背景，補存到 IndexedDB。
- 每個檔案有內容 SHA-256 revision；啟用新版本時刪除過期路徑及不同 revision。每 24 小時首次使用後再於背景重新檢查。
- 儲存被拒絕、容量不足或 IndexedDB 失效時仍讀取網路圖片。HTML、登入資料及使用者成績不屬於這個圖片快取。
- 新增或修改清單圖片後，執行 `node scripts/update-entry-image-manifest.mjs` 更新 revision；測試會驗證清單、檔案與雜湊相符。

## 驗證

- `npm run check` 成功：74 個測試檔、659 個測試、型別檢查與全部既有建置通過。
- 新增 7 個快取測試：跨 Worker 讀取、版本清理、容量淘汰、儲存失敗、白名單及查詢參數、404 不保存、內容 revision 一致。
- 實際 Chrome 本機測試：伺服器全部回應設為 Cache-Control: no-store。主星球 JPEG、透明分頁 PNG、收藏品 JPEG、共用 SVG 都回傳 `X-LP-Image-Cache: indexeddb`。
- 讓測試伺服器對所有圖片回傳 503 後，上述四類資源仍是 200 indexeddb，重新開頁後仍成功；未列入快取的頭像確實為 503。這次證據可區分 IndexedDB 與一般 HTTP 快取。
- 實際登入頁進度顯示 100%，七張登入圖片正常讀取。
- 原有建置產生的無關檔案已復原；未改動實驗模組。

未宣稱正式網站或 iPad 的速度提升秒數；這些需要發佈後另行量測。瀏覽器仍可能清除本機儲存，首次使用仍須下載圖片。
