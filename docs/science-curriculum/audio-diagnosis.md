# 朗讀失敗的原因區分與修正

更新：2026-11-12。範圍為本機候選版、原生桌面 Chromium。以下音訊實測來自前輪 v2 診斷及修復驗證，不是目前 v3 最終資料與全部模式的完整重驗。未操作真實學生帳戶、使用麥克風或新增外部語音服務。

## 環境對照的結論

失敗集中於當時環境的瀏覽器語音合成路徑，不能歸結為整個裝置沒有音訊，也不能據此宣稱其他裝置朗讀已通過。

- 頁面可取得 `speechSynthesis` 與 `SpeechSynthesisUtterance`。
- 載入、`voiceschanged`、250毫秒、1秒及3秒時語音清單都為0；修復後頁面載入68.35秒後手動讀取仍為0。
- 不載入課程程式的最小原生中文（zh-TW）、英文（en-US）與預設語系測試，皆在真實點擊且使用者啟用狀態為真的情況下，呼叫 `speak` 後收到 `synthesis-failed`。字元位置為0，沒有開始或結束事件。
- 課程模組得到相同錯誤。最小原生測試沒有先呼叫取消，因此不能只歸因於候選模組的取消流程。
- Web Audio 在 running 狀態產生44.1kHz訊號，取樣 RMS 約0.05663，0.3秒後正常結束並關閉。
- 本機短 WAV 經 HTML Audio 的 `play()` 成功，從 playing 到 ended，時間與長度均為0.3秒，沒有媒體錯誤。

對照顯示不是只有候選介面失敗，也不是所有瀏覽器音訊播放都被阻擋；但通用的 `synthesis-failed` 不能指出作業系統究竟缺少哪個套件、服務或設定。沒有修改作業系統音訊或安全設定，也沒有安裝語音引擎。

數位訊號與媒體事件不是實際喇叭聲音或聽感證明。本次沒有成功中文語音聽測。

## 已修復的程式缺陷與前輪驗證

1. 音訊錯誤原本重新建立整個任務表單。舊版實際重現未加入草稿被清空、日期重設、區塊收合與焦點跳回標題。
2. 語音清單讀取例外原本會阻止後續預設朗讀。選聲音的輔助資訊不能單獨決定是否嘗試播放。

修復使用獨立單一狀態節點，在被點擊按鈕旁提示錯誤，重試清除舊提示；不重建表單、不主動捲動或改焦點。草稿不會因朗讀自動變成觀察證據。

語音清單空白或讀取失敗時，仍在同一次同步點擊中以 zh-TW 嘗試瀏覽器預設語音，不用延遲重試繞過手勢要求。錯誤碼對應固定提示，不直接顯示外部錯誤內容；取消、切題、隱藏、關閉與過期回呼保留防護。

前輪修復後連續3次實測聽任務（含第二任務），草稿、日期、展開狀態與焦點皆保留，整頁只有一個提示。聽題目失敗後仍可作答、看解說與下一題。這些是錯誤處理與資料保護證據，不能替環境產生可用語音服務，也不能標成 v3 成功出聲。

## 可重現與待補驗項目

- 執行 `npm run test:science-curriculum` 核對草稿、日期、焦點、重試、錯誤分類、過期回呼與紀錄隔離；v3 最終全專案檢查仍須另行記錄。
- 在本機 HTTP 服務開啟 `qa/science-curriculum/audio-diagnostic.html`。此診斷頁僅允許 localhost，可比較最小原生語音、課程模組、Web Audio 與本機 WAV，不連外部語音服務。
- 於確實可播放中文語音的裝置實聽：讀音、長任務完整播放、連續點擊，以及播音中切題／背景／關閉；另補 iOS Safari、Android 等目標裝置。
- 對最終 v3 題庫及舊主題模式重新檢查音訊失敗與輸入保護。成功播放期間的切頁競態不能由失敗路徑或 DOM 測試代替。
- 遠端 CI 只驗程式與建置，不證明實際出聲；目前遠端 CI 未執行。部署已獲授權，但仍待最終檢查與核實發布，發布後的頁面與資源時間尚未量測。
